# Skill

## Purpose

This document defines the skill profile that the portfolio is trying to demonstrate. It is aligned to a Senior/Lead AI Backend Engineer position and emphasizes systems design, operational discipline, and ML-aware backend execution.

## Core skill areas

### 1. Distributed systems and backend engineering

- API design and versioning
- service boundaries
- queue-based async patterns
- idempotency and retry policies
- resource isolation and deployment hygiene

### 2. Platform engineering and operations

- Kubernetes or container orchestration fundamentals
- namespace isolation
- network policies and workload identity
- observability and alerting
- incident response and runbooks

### 3. AI and inference systems

- model-serving boundaries
- prompt logging and versioning
- latency and throughput constraints
- safety controls and policy gates
- local-model deployment considerations

### 4. Data flow and event architecture

- Kafka and event contracts
- dead-letter handling
- schema evolution
- telemetry ingestion and replay
- streaming failure management

### 5. Reliability and security

- threat modeling
- access control design
- auditability
- chaos testing
- production-grade failure handling

## Evidence expected for each skill area

A strong skill signal should be backed by artifacts such as:

- ADRs
- architecture diagrams
- system design writeups
- tests and load-test outputs
- deployment or local-run instructions
- recorded demos

## Skill story

The user is not claiming to be a pure ML researcher. The portfolio should read as:

> A backend-first engineer who understands production AI systems, reliability constraints, and security trade-offs.

That story is much stronger for hiring than a collection of disconnected toy models or demos.

## Summary

The goal is not volume of skill but clarity of signal. Every piece of work should make the user look like a trustworthy builder of AI systems that can run safely and reliably in production.
