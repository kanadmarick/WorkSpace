# Task

## Purpose

This document defines the work units that support the pursuit of a Senior AI Backend Engineer role. Each task is framed around evidence and execution quality.

## Task model

Each task should represent a concrete work unit with:

- objective
- expected output
- proof required
- relationship to role target

## Core tasks

### Task 1: Positioning baseline

Objective: Create a credible personal narrative and architecture brief.

Deliverable:

- one-page architecture brief for Sentinel, Hadron/Aether, and Zenith

Proof:

- published markdown or GitHub-ready summary

### Task 2: Infrastructure isolation

Objective: Demonstrate platform-level rigor.

Deliverable:

- namespaced deployment model
- network policy and workload identity plan

Proof:

- ADR and architecture diagram

### Task 3: Event-driven telemetry

Objective: Show understanding of data flow and system health.

Deliverable:

- component event contracts
- observability stack and SLOs

Proof:

- metrics dashboard or runbook

### Task 4: Safety and inference controls

Objective: Show AI systems can be constrained and audited.

Deliverable:

- action allowlist
- inference gateway
- prompt logging

Proof:

- decision path documentation and demo

### Task 5: Validation and chaos tests

Objective: Show resilience under realistic failure modes.

Deliverable:

- load test
- failure injection experiment
- recovery plan

Proof:

- recorded output or result summary

### Task 6: Hiring loop

Objective: Convert evidence into interview readiness.

Deliverable:

- architecture case study
- mock interview loop
- application tracking

Proof:

- recorded answers or review notes

## Task execution rule

A task is complete only when there is evidence that it was executed, reviewed, and recorded.

## Summary

The task system keeps work concrete and measurable. It is intentionally designed to avoid vague progress and to ensure that every engagement supports the final career objective.
